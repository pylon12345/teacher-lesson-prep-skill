# 问题简报：教师备课 Skill

> 用 PM OS 的 assess 模式评估「这个 Skill 值不值得继续投入、下一步该做什么」。
> 标记：[事实] 有依据；[假设] 我们的推测；[待验证] 需要真实老师来证明。

## 一句话问题

[假设] 老师每周要备很多节课，现成的教案（教参、下载站、AI 直接生成）不贴合自己的班级和风格，改起来仍然费时；准备优质课时，磨课意见多、版本多，过程乱、容易丢。

注意：这句话里「AI 生成教案」本身不是问题，只是一种解法。

## 两个不同的任务（JTBD）

| | 任务 A：日常备课 | 任务 B：优质课 |
|---|---|---|
| 触发 | 明天要上课 / 学校要查教案 | 要参加赛课、公开课 |
| 老师想要 | 快、够用、能交差也能上课 | 质量高、拿奖、被认可 |
| 频率 | 每周多次 | 一学期 0～2 次 |
| 愿意花的时间 | 少 | 很多（几周，多轮试讲） |
| 现在怎么做 | 下载改、用旧教案、手写简案 | 教研组磨课、看名师课例、反复改 |
| 成功标准 | 省时间 | 课上得好、评委认可 |

**产品含义**：日常备课要短、快，不要一上来就追问一堆；优质课可以深，要管好版本和磨课意见。同一套流程不能同时满足两者。

## 证据

### [事实]
- 仓库里的流程、模板、优质课顺序都是根据网上公开资料整理的（2026-09-26 检索），不是来自真实老师。
- 目前没有任何老师用过这个 Skill。

### [假设]
- 老师愿意把自己的资料放进一个知识库，并且会持续往里加。
- 贴合个人和班级的教案，比通用教案明显更省改的时间。
- 磨课版本管理是优质课老师的真实痛点。
- 老师能用上 Claude Code，或愿意装。

### [待验证]
- 老师用它备出来的课，有多大比例真的拿去上了？
- 相比现在的做法，每节课省了多少时间？
- 老师第二次会不会主动再用？

## 当前替代方案

老师现在不用我们也能备课，所以我们要赢的是这些：
1. **学科网等下载站 + 自己改**：内容多、免费或便宜，但不贴合。
2. **豆包 / Kimi / DeepSeek 直接问**：零门槛、国内能用、免费。
3. **自己去年的教案**：最贴合，改改就能用。
4. **学校集体备课的共享教案**：有时是强制的，必须用。

差异点只能是：**知识库带来的个人化 + 学情 + 磨课记录的积累**。如果老师不维护知识库，我们和「豆包直接问」没有区别。

## 四类风险

| 风险 | 现有证据 | 最大未知 | 下一步验证 |
|---|---|---|---|
| 价值：老师真的需要吗 | 无 | 比现在的做法好多少 | 找 3～5 位老师用真实的课试 |
| 可用性：老师会用吗 | 无 | 知识库会不会维护、流程会不会嫌长 | 观察老师第一次使用 |
| 可行性：做得出来吗 | Skill 已能生成教案 | 教材原文不在时会不会编造 | 行为测试 `tests/cases.md` |
| 可持续：渠道和使用环境 | 无 | **国内老师能不能用上 Claude；老师会不会用终端和 git** | 先问目标老师平时用什么 AI 工具 |

**最危险的假设**：老师能在 Claude Code 里备课，并且会维护知识库。
这一条不成立，其他功能做得再好也没人用。

## 结论

- **建议阶段**：继续 Discovery，并做一个人工代跑的 MVP，见 `mvp.md`。
- **理由**：功能已经足够验证核心价值，再加功能（大单元、PPT、出题）是在没有证据的基础上继续投入。
- **暂停 / 停止条件**：见 `mvp.md` 第 6 节。
