# 试点操作手册

配合 `product/mvp.md` 使用。这一轮只验证一件事：**老师拿到用自己资料生成的教案，会不会真的拿去上课，并且主动再来用。**

## 隐私：真实记录不进仓库

这个仓库是公开的。老师的材料、反馈、班级情况、教材照片**只放在本机的试点目录**（默认 `C:\Users\gao\备课试点\`），不要放进仓库，也不要提交到 GitHub。

- 老师用代号（T01、T02……），不写真实姓名和学校。
- 学生一律不写真名。
- 教材照片只用于试点，结束后问老师要不要删。
- 仓库里的 `product/evidence.md` 只写去掉身份信息的汇总结论。

## 试点目录结构

```
备课试点/
├── 记录.csv                   每节课一行（模板见 records-template.csv）
└── 老师/
    └── T01/
        ├── 备课知识库/         从 kb-template 复制，按访谈内容填档案
        ├── 材料/               老师发来的照片、文件，原样保存
        └── 输出/               Skill 生成的教案，原样保存
```

## 流程

### 0. 开始前（一次）

1. 确认 Skill 已安装，版本固定为 `pilot-v1`（试点期间不要改 Skill，否则前后结果没法比）。
2. 把 `records-template.csv` 复制到 `备课试点/记录.csv`。

### 1. 邀请老师

用 `invite.md` 里的话术。3～5 位，每人 2～3 节**真实要上的课**，不要专门挑课来试。

### 2. 首次访谈（每位老师一次，10～15 分钟）

按 `interview.md` 第一部分。访谈结束后：
1. 建 `老师/T0x/备课知识库/`（复制 `kb-template/`）。
2. 把老师说的整理进 `00-我的档案.md` 和班级学情，**发给老师看一眼确认**。

### 3. 每次备课

1. 老师按 `invite.md` 里的格式发来材料，原样存进 `材料/`。
2. **在 `老师/T0x/` 目录下打开 Claude Code**（这样 Skill 会自动找到这位老师的 `备课知识库/`）。
3. 把老师的原话和材料原样交给 Claude，比如：「T01 老师发来的，帮她备这节课」+ 附件。
4. 生成的教案原样存进 `输出/日期-课题.md`。
5. **尽量不手动改就发给老师。** 如果必须改，在记录里写清楚改了什么——这是 Skill 的缺陷证据，比教案本身更有价值。
6. 在 `记录.csv` 里记一行：用时、你改了什么。

### 4. 老师上完课

1. 用 `interview.md` 第二部分的课后问题问老师（微信发，1 分钟能答完）。
2. 老师原话记进 `记录.csv`。
3. 老师愿意的话，用 Skill 的「课后反思」模式把反思存进这位老师的知识库——下次备课就能用上，这正是要验证的差异点。

### 5. 每周看一次

- 教案被拿去上课的比例
- 老师改掉的地方有没有规律（例如总是删导入、总是嫌活动太多）
- 有没有老师**没被催就主动**发来下一节课

### 6. 两周后复盘

按 `mvp.md` 第 6 节的门槛判断：通过 / 迭代 / 停止或转向。结论写进 `product/evidence.md`（汇总、去身份），决策写进 `product/decisions.md`。

## 怎么看证据

- 「挺好的」「很有用」**不算证据**。看行为：有没有拿去上课、改了多少、有没有主动再来。
- 老师改掉的地方比留下的地方更值得记。
- 一位老师的强烈意见，先当一条线索，等第二位老师也出现同样情况再下结论。
- 不要在试点中途改 Skill。发现问题先记下来，试点结束后统一改，再开下一轮。
