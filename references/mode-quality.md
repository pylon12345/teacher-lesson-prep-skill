# 模式：优质课

目标：帮老师把一节课打磨到能拿去比赛或公开展示。流程和评价维度见 `references/quality-lesson.md`。

## 开始前确认（最多 3 问）

1. 比赛或活动的**评分标准**有没有？（知识库 `05-评课意见/` 里找，没有就问）
2. 现在进行到哪一步：还没开始 / 有初稿 / 试讲过几轮？
3. 课时长、上课的班级是不是自己的班（借班上课学情完全不同）？

评分标准是最重要的输入。没有就用通用维度，并标 `[假设]`。

## 按阶段做事

### 还没开始 → 初稿 v1
- 用 `templates/lesson-plan.md` 出详案。
- 附一张**评分对齐表**：评分表每一项 → 教案里哪个环节回应它 → 风险。

### 有初稿 → 逐字稿
- 用 `templates/lecture-script.md`。
- 每个关键提问都写三种学生回答预设（对 / 部分对 / 错）和老师怎么接。
- 时间要能对上：按每分钟约 180～220 字估算老师讲话时长 [假设]，超了就删。

### 试讲后 → 磨课
老师把评课意见发来（文字、语音转写、截图都行）：
1. 用 `templates/polish-log.md` 逐条记录**原话**，归类，写处理意见：改 / 不改 / 待定。
2. 意见互相矛盾时（例如一个说导入太长、一个说导入不够充分），不要自己挑一个，列出来让老师定。
3. 老师决定不改的，写下理由，防止下一轮又被提。
4. 出新版本，版本号 +1，**不覆盖旧版**。写清这一版改了什么。

### 定稿 → 说课稿
- 用 `templates/talk-script.md`。说课讲的是「为什么这样设计」，不是把教案再念一遍。

## 边界

- 不替老师决定采纳哪条评课意见；可以给建议，但决定权在老师。
- 名师课例可以借鉴结构，不要整段照搬别人的教学设计。
